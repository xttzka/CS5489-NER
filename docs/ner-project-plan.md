# 多领域命名实体识别：从 CRF 到 LLM 的系统对比（项目计划）

Nov 4, 2026 · @seven

## 1. 引言

### 1.1 背景

- CoNLL-2003 共享任务中英文最佳系统 F1 为 88.76，基于预训练 Transformer 的模型已超过 90。
- 同一篇论文的基线只识别训练集中类型唯一的实体，F1 即达 59.61，说明该基准上相当一部分性能可以通过记忆训练实体获得；论文还指出训练数据取自 1996 年 8 月、测试数据取自 12 月。
- Liu 和 Ritter（ACL 2023）用 2020 年的 Reuters 新闻按同一规范构建了 CoNLL++，用于检验时间泛化。
- 零样本 NER 模型（如 GLiNER）和指令调优的小型 LLM 提供了不依赖目标领域标注、可接受任意类型名的路线。

### 1.2 主任务与交付

题目的主任务是开发一个能从输入句子中输出实体短语的 NER 抽取器，并在指定数据集上评测。本项目在 CoNLL-2003 上构建一系列抽取器，从中按验证集 F1 选出**主抽取器**，它在测试集上的 P、R、F1 及置信区间是项目的主结果（§5）。在此基础上，在统一的数据格式、评测函数和统计检验下，把主抽取器放在从特征工程到 LLM 的一系列方法中比较，分析性能来源、泛化能力和代价（§6 与 §7）。

题目提到的两类方法都覆盖：序列标注（逻辑回归、CRF、BiLSTM-CRF、BERT），以及序列标注以外的方法（Span 分类、GLiNER 的 span 匹配、LLM 的生成式抽取）。

### 1.3 要回答的五个问题

1. 主抽取器的性能从哪里来：记忆、手工特征、标签序列建模、预训练表示各贡献多少？（§6.1）
2. 它是记住了名字，还是学会了识别？未见实体、实体替换和时间漂移下表现如何？（§6.2）
3. 换到推特、社交媒体、维基百科和搜索查询后还剩多少？损失能否由数据集重叠程度和书写风格解释？（§6.3）
4. 不用目标领域标注、遇到新实体类型时，零样本模型与小型 LLM 能走多远？误差来自哪里？（§7.1）
5. 组合方法能否在准确率、推理成本和标注规范一致性之间取得更好的平衡？（§7.2）

五个问题依次递进：第 1 个找出主要性能来源；第 2 个针对其中的实体记忆做直接检验；第 3 个把检验扩展到实体分布与书写风格同时变化的领域；第 4 个评估专为无标注和新类型设计的方法；第 5 个针对前两个问题中观察到的权衡提出组合方案。§8 汇总全部结果，给出方法选择建议。

### 2.1 三种使用方式

1. **域内基准**：在 CoNLL-2003、WNUT-17、MIT Restaurant 上分别训练和测试，得到「方法 × 数据集」分数表，比较各方法在不同文本类型上的排名。
2. **迁移矩阵**：以 CoNLL-2003、WNUT-17 以及两者合并为训练源，在 CoNLL-2003 测试集、CoNLL++、WikiGold、BTC、WNUT-17 测试集的共有类型（PER、LOC、ORG）上评测，得到「训练源 × 测试集」矩阵。
3. **新实体类型**：在 MIT Restaurant 上比较零样本方法（GLiNER、LLM）与使用 50 句、100 句和全部标注训练的 BERT，测量零样本方法追平监督学习所需的标注量。

### 2.2 格式统一与标签映射

- 全部数据转成同一种 JSONL 格式（tokens、tags、dataset、split），所有模型和评测函数只读这一种格式。
- CoNLL 的 `ner_tags` 编号：O=0，B-PER=1，I-PER=2，B-ORG=3，I-ORG=4，B-LOC=5，I-LOC=6，B-MISC=7，I-MISC=8，IOB2 格式。HF 版删除了 `-DOCSTART-` 文档分隔行，句子数为 train 14,041、validation 3,250、test 3,453。该仓库依赖加载脚本，较新版本的 `datasets` 库可能拒绝运行，届时固定旧版本或读取原始文件。
- 只有 CoNLL 自带 POS 和 chunk 标签。为了让 CRF 在所有数据集上使用同一套特征，统一用 spaCy 重新标注全部数据集的词性。
- 跨数据集标签映射写进报告附录：WNUT-17 的 person 对应 PER，location 对应 LOC，corporation 和 group 对应 ORG；product 和 creative-work 在迁移评测中不计。迁移评测只计算共有类型 PER、LOC、ORG。
- MIT Restaurant 的类型名改写为自然语言描述（如 Dish 写作「菜品名称」），作为 GLiNER 和 LLM 的类型输入。
- MIT Restaurant 没有验证集，从训练集中按连续块切出 10% 作为验证集。
- 第 1 到 3 天逐个核实下载方式、标签集、句子数和许可证。

## 3. 方法

全部抽取器分为序列标注与序列标注以外两组。序列标注组按复杂度排成一个序列，相邻两个只差一个因素，性能差值可以直接归因。

### 3.1 序列标注

| 编号 | 方法 | 相对前一方法新增的因素 | 负责 |
| --- | --- | --- | --- |
| M0 | 词典基线：只识别训练集中类型唯一的实体，取最长匹配（复现论文基线） | 起点：纯记忆 | A |
| M1 | 逐 token 逻辑回归，手工特征 | 上下文特征 | A |
| M2 | 线性链 CRF，与 M1 完全相同的特征 | 标签序列建模 | A |
| M3 | BiLSTM-CRF，词向量加字符级 CNN | 学习得到的稠密表示 | B |
| M4 | bert-base-cased 微调，每个词取第一个子词的标签 | 大规模预训练 | B |

### 3.2 序列标注以外

| 方法 | 做法 | 选它的理由 | 负责 |
| --- | --- | --- | --- |
| Span 分类 | 枚举长度不超过 L 的片段，用 BERT 首尾向量加长度特征分类 | 以整个实体为预测单位，检验能否减少 BIO 标注的边界错误 | B |
| GLiNER | 把类型名作为文本输入的编码器模型，不训练直接抽取 | 小模型的零样本路线，可处理任意新类型 | C |
| LLM 提示 | Qwen2.5 两个规模，零样本与少样本提示，输出 JSON 实体列表 | 生成式抽取，带有世界知识；零样本不需要标注，少样本只需少量标注作示例 | C |
| LoRA-LLM | 用标注数据对小规模 Qwen2.5 做 LoRA 微调，生成式输出 | 让 LLM 学会数据集的标注规范 | C |
| LLM 标注蒸馏 | LLM 给未标注句子打标签，再训练 BERT | 把 LLM 的能力装进快速的小模型 | C |
| 集成 | 多个方法的实体级多数投票 | 利用不同范式错误的互补性；共享任务论文中五系统投票把 F1 从 88.76 提到 90.30 | A |

### 3.3 特征与表示

- **CRF 手工特征**（参照共享任务论文表 3）：G1 词汇（词形、小写形式）、G2 正字法（大小写、数字、连字符、词形模式如 Xxxx）、G3 词缀（2 到 4 字符前后缀）、G4 句法（POS、chunk）、G5 上下文窗口（前后 1 或 2 个词）。
- **新特征**：词聚类 ID（对 GloVe 词向量做 K-means，簇编号作为特征）；地名词典匹配特征。
- **神经模型输入表示**：随机初始化、GloVe、GloVe 加字符级 CNN、BERT 冻结特征、BERT 微调。

### 3.4 模型与工具选型

| 用途 | 选型 | 说明 |
| --- | --- | --- |
| LLM 提示（两个规模） | Qwen/Qwen2.5-1.5B-Instruct、Qwen/Qwen2.5-7B-Instruct | 同一系列，只有规模不同，规模对比才干净；两者均为 Apache 2.0 许可 |
| LoRA 微调 | Qwen2.5-1.5B-Instruct + PEFT | 与提示实验同一模型，才能分离出微调本身的作用 |
| 零样本 span 模型 | urchade/gliner\_medium-v2.1 | 约 2 亿参数 |
| 监督预训练模型 | bert-base-cased | M4、Span 分类、蒸馏学生模型共用 |
| 静态词向量 | GloVe 6B 100d | 词表是小写的，BiLSTM-CRF 的大小写信息只能来自字符级 CNN，在 §6.1 中作为分析点 |
| 示例检索的句向量 | sentence-transformers/all-MiniLM-L6-v2 | 按相似度选少样本示例 |

## 4. 实验设置：验证、交叉验证与显著性

规则只有一条：**test 只在所有调参结束后评估一次**，所有选择都在 train 交叉验证或 dev 上完成。这一条直接对应 Experiment Setup 的 10 分。

### 评测指标

- 主指标：实体级 micro F1（精确匹配，边界和类型都对才算对），与 CoNLL-2003 共享任务一致，用 `seqeval` 计算。
- 同时报告 precision、recall 和每类 F1。token 准确率作为对照列出一次，用数字说明 O 标签占多数时它为何偏高。

### 各方法的调参方式

| 方法 | 调参数据 | 搜索的超参数 | 结果报告方式 |
| --- | --- | --- | --- |
| CRF | train 上 5 折交叉验证 | L1 系数 c1、L2 系数 c2、特征窗口大小 | 5 折均值 ± 标准差，再用最优参数在全量 train 上重训 |
| BiLSTM-CRF | dev | 隐层维度、dropout、学习率 | 3 个随机种子的均值 ± 标准差 |
| BERT 系 | dev | 学习率、epoch 数、batch size | 3 个随机种子的均值 ± 标准差 |
| LLM 抽取 | dev 的固定子集 | 提示模板、示例数量 k | 不训练，只选提示 |

交叉验证的细节：HF 版没有文档边界，同一篇新闻的句子相邻。折分时按**连续句子块**切，不要随机打乱句子，否则同一文章同时出现在训练折和验证折，会高估 F1。报告里可以加一个小实验：随机切与按块切的 CV 分数差多少，这本身就是一个关于数据泄漏的发现。

多数据集下的规则：每个域内基准单独调参，各自在自己的训练集上交叉验证或在自己的 dev 上选参数；迁移实验沿用源数据集上选出的超参数，目标数据集的测试集只用于测量。

### 显著性检验

参考共享任务论文的做法：对测试集句子做 bootstrap 重采样（论文用 250 次；我们用 1,000 次），给每个系统的 F1 一个置信区间，并对两两系统做配对 bootstrap。只有区间不重叠或配对检验显著，报告里才写「A 优于 B」。

### 可复现

- 固定随机种子，每次运行把配置和结果写进同一个结果表（CSV），图都从这张表生成。
- 三人共用同一个评测函数，保证分数可比。

## 5. 主结果

主任务在这一节完成：给出全部抽取器在 CoNLL-2003 上的结果，选出主抽取器，并在另外两个有训练集的数据集上复现比较。

**5.1 方法序列（A、B）**。M0 到 M4 与 Span 分类在 CoNLL-2003 上的 F1 与逐级增益。参照值：M0 对照论文基线 59.61，M2 对照论文中 CRF 系统的 84.04。M1 与 M2 之间另报告非法 BIO 序列数（如 O 后接 I-PER），衡量标签序列建模的作用；M4 与 Span 之间另报告边界错误占比，检验整实体预测是否减少边界错误。BERT 用 3 个随机种子。

**5.2 主抽取器（B）**。按 CoNLL-2003 验证集 F1 从全部监督方法中选出（预期为 BERT 或 Span 分类），在测试集上只评测一次，报告总体与分类型的 P、R、F1 及 bootstrap 置信区间。这是摘要第一句写的数字，也是 `predict.py` 的默认模型。

**5.3 域内基准（A、B）**。全部监督方法在 CoNLL-2003、WNUT-17、MIT Restaurant 上分别训练和测试（A 负责 M0 到 M2，B 负责 M3、M4、Span），比较各方法的排名是否随文本类型变化。§7 的零样本方法结果并入同一张表。

**预期与引出的问题**：预期记忆基线已占据大部分分数，每一级的增益逐渐变小；排名在噪声文本和查询数据上发生变化。这引出 §6.1：高分的各个成分各占多少。

## 6. 分析

### 6.1 性能从哪里来

**动机**：§5 的方法序列只给出了每一级的总增益。要知道增益具体来自哪类信息，需要在特征、输入表示和表示空间三个层面拆开看。

**假设**：正字法特征（尤其大小写）对 CRF 的贡献最大；上下文表示比静态词向量提升明显；预训练表示在没有任何标注时就已按实体类型分团。

- **(a) 手工特征消融（A）**：在 CRF 上逐组删除 G1 到 G5，全部用 5 折交叉验证，按实体类型报告 F1 损失。
- **(b) 输入表示对比（B）**：固定 BiLSTM-CRF 结构，只更换输入：随机初始化、GloVe、GloVe 加字符级 CNN、BERT 冻结特征。GloVe 词表是小写的，因此「加字符级 CNN」一档同时衡量了大小写信息的作用。
- **(c) 表示空间的降维与聚类（B 导出向量并画图，A 聚类）**：实体向量取实体内子词向量的平均，分别来自 GloVe、未微调 BERT、微调后 BERT，用 t-SNE 降到二维并按类型着色；对三种表示做 K-means（k=4），用 ARI 与 NMI 衡量与真实类型的一致性；对 MISC 单独聚类并人工检查各簇，解释 MISC 为何分数最低。

**对应图表**：F3、F4。**引出的问题**：如果性能很大程度来自对训练实体的记忆和大小写线索，模型在未见实体上的表现需要单独检验。

### 6.2 记住名字，还是学会识别

**动机**：CoNLL-2003 测试集与训练集来自相隔几个月的同一新闻源，大量实体重复出现，总体 F1 无法区分「记住了名字」与「根据上下文识别实体」。

**假设**：所有监督方法在未见实体上的 F1 显著低于见过的实体，差距从 M0 到 M4 逐步缩小；实体替换后依赖词汇特征的方法下降最多；2020 年的 CoNLL++ 上的下降集中在未见实体；词聚类 ID 与地名词典主要提升 CRF 在未见实体上的表现。

- **(a) 见过与未见实体分开评测（A）**：按测试实体字符串是否出现在训练集中分为两组，对全部方法分别计算 F1。
- **(b) 实体替换测试（A 构建，B、C 运行各自模型）**：把测试句中的实体替换为同类型、训练集未出现的名字，上下文不变，性能差异只来自实体名本身。
- **(c) 时间泛化（A）**：全部 CoNLL 训练的模型直接在 CoNLL++ 上测试，并同样按见过与未见实体拆分。
- **(d) 泛化特征（A）**：在 CRF 上加入词聚类 ID（k 取 100、500、1000，让未见词与语义相近的已见词共享簇编号）和地名词典特征（依据论文表 4：使用外部信息的 11 支队伍都用了地名词典），在全部实体、未见实体和 CoNLL++ 上分别报告增益。

**对应图表**：F5（四个面板对应 a 到 d）。**引出的问题**：CoNLL++ 仍是同一新闻源、同一书写风格，只改变了实体分布；实体分布和书写风格同时改变时会怎样。

### 6.3 换领域后还剩多少

**动机**：实际文本同时改变实体分布和书写风格：推特大小写不规范，社交媒体充满新出现的实体，搜索查询全小写。本节把这两个因素分开测量。

**假设**：迁移损失与源、目标数据集的实体重叠率负相关；正字法线索在推特和查询数据上失效，是这些领域掉分的主要来源之一；两源合并训练在未参与训练的领域上更稳定。

- **(a) 迁移矩阵（B，A 提供 CRF 结果）**：以 CoNLL-2003、WNUT-17 及两者合并为训练源，在 CoNLL-2003 测试集、CoNLL++、WikiGold、BTC、WNUT-17 测试集的共有类型（PER、LOC、ORG）上测试 BERT 与 CRF；合并训练一行重点看 WikiGold 与 BTC。
- **(b) 迁移损失的解释（A）**：以「训练源 × 测试集 × 实体类型」为单位，用 §2 统计的实体重叠率对性能损失做相关与回归分析。
- **(c) 大小写线索的作用（A 消融与构建扰动集，B、C 运行各自模型）**：一是在 CoNLL、WNUT-17、MIT Restaurant 上域内重做 G2 正字法特征的消融，并在 BTC 上比较有无 G2 的 CoNLL 训练 CRF；二是对 CoNLL 测试集做全部小写、5% 字符级拼写噪声、删除标点三种扰动，实体与上下文不变。将全小写造成的下降与 (a) 中 BTC 的迁移损失对照，估算大小写对推特掉分的贡献。

**对应图表**：F6、F7。**引出的问题**：监督模型换领域就掉分，固定标签集也处理不了 MIT Restaurant 的新类型，而为每个领域重新标注代价很高，由此进入 §7。

## 7. 延伸：零样本、LLM 与组合方法

### 7.1 不用标注能走多远

**动机**：§6.3 预期显示，监督模型迁移到新领域会显著掉分，遇到新实体类型则必须重新标注。零样本 NER 模型和指令调优的 LLM 不需要目标领域标注，并接受任意类型名，正好对应这两个问题。

**假设**：零样本方法在 CoNLL-2003 上低于监督模型，但在新实体类型和跨领域场景下与迁移过来的监督模型差距缩小甚至反超；LLM 的错误中相当一部分来自与标注规范不一致，提示中加入规范说明后差距缩小；存在一个标注量交叉点，低于它时零样本方法优于监督 BERT，且新类型上的交叉点更高；标注量很少时，把标注给 LLM 作示例优于用它们训练 BERT；示例按相似度检索优于随机选取。

- **(a) 零样本方法的整体表现（C）**：GLiNER 与不带示例的 LLM（两个规模）在 6 个数据集各自固定的 300 句测试子集上评测，类型名改写为自然语言描述，这两类方法不使用任何目标领域标注；所有监督方法也在同一子集上报告。(b) 选出的带示例配置作为少样本方法单列一行，注明示例取自训练集。MIT Restaurant 上按类型拆开，说明哪些类型零样本就能识别、哪些必须靠标注学会边界。
- **(b) LLM 提示变量（C）**：Qwen2.5-1.5B-Instruct 与 Qwen2.5-7B-Instruct，输出固定为 JSON。在 CoNLL 验证集固定 300 句上每次只改一个变量：示例数量（0、1、5、10）、示例选择（随机与相似度检索）、标注规范（只给类型名与附上规范要点）、模型规模。示例取自训练集中至少含一个实体的句子，带示例的配置使用了训练标注，归为少样本。JSON 解析失败率与幻觉率单独统计。
- **(c) 标注量交叉点（B 训练，C 分析）**：在 CoNLL-2003、WNUT-17、MIT Restaurant 上用 50 句、100 句及 1%、10%、100% 训练数据训练 BERT（50 句与 100 句两档用 3 个随机种子），零样本结果画成水平线，找出交叉点。少样本 LLM 的示例检索池限制为同样的五档标注，抽样方式与 BERT 的训练样本相同，画成第二条曲线，B 与 C 都调用 `models/llm/common.py` 的 `sample_train(dataset, size, seed)` 抽取各档标注（50 句与 100 句用种子 0、1、2，其余用种子 0），保证两条曲线每一档用的是同一批句子，在同一标注量下比较「用这些标注训练 BERT」与「把这些标注给 LLM 作示例」。
- **(d) LLM 误差分析（C，A 作为第二判断人）**：用与监督模型相同的自动工具，把 LLM 在 CoNLL 与 WNUT-17 上的全部错误分为边界错误、类型错误、误报、漏检，误报中输出实体不在原句的自动记为幻觉。规范不一致无法自动判断：从类型错误和误报中随机抽 60 个，两人独立做三选一判断（规范不一致、金标错误、其他），计算 Cohen's kappa，并用抽样比例估计规范不一致的占比。加入规范说明前后各做一次，每人每次约 20 分钟。

**对应图表**：T3（零样本行）、F8、F9。**引出的问题**：预期零样本方法在新类型上占优、在 CoNLL 上落后且错误集中于规范不一致，推理也远慢于监督模型。两类方法之间存在明显权衡。

### 7.2 能否兼得准确、便宜、守规范

**动机**：针对 §7.1 的权衡检验三种组合思路：用标注数据让 LLM 学会规范，用 LLM 生成标注训练快速的小模型，以及利用不同方法错误的互补性。

**假设**：相同训练数据下，LoRA 微调的小型 LLM 域内接近 BERT、跨领域优于 BERT，但推理更慢；没有人工标注时，LLM 标注蒸馏的 BERT 准确率接近零样本 LLM，推理速度达到 BERT 的水平；不同范式方法的错误重叠较低，跨范式投票能超过最佳单一模型。

- **(a) LoRA 微调（C）**：用 Qwen2.5-1.5B-Instruct 在 CoNLL 训练集的 10% 上做 LoRA 微调，与同样 10% 数据的 BERT（取自 §7.1 (c)）和同一 LLM 的提示结果比较域内与迁移 F1、可训练参数量和推理速度。
- **(b) LLM 标注后蒸馏（C 生成标注，使用 B 的训练脚本）**：从 MIT Restaurant 训练集抽 2,000 句并去掉标签，由不带示例的 7B LLM 重新标注后训练 BERT；对照同样 2,000 句人工标注训练的 BERT 与零样本 LLM，并报告自动标注本身相对人工标注的 F1。
- **(c) 集成（A）**：计算各方法两两之间的错误重叠（Jaccard），比较同范式与跨范式多数投票的增益。
- **(d) 成本与性能（A 汇总，各成员记录自己的日志）**：所有方法记录训练时间、每秒处理句数、显存峰值与可训练参数量，画出 F1 对推理速度的帕累托前沿；稳定性用随机种子与提示措辞的标准差衡量。

**对应图表**：T4、F10。预期蒸馏在成本与准确率之间提供最实用的折中，跨范式集成取得最高分但成本最高；完整比较在 §8 汇总。

### 12.2 图表规范

全组所有图都调用同一个样式文件 `analysis/style.py`（只由 A 修改），保证字体、尺寸和颜色在报告与视频中完全一致。

**通用规则**

- 字体：Times New Roman，公式用 STIX（与 Times 匹配）。图中正文 9 pt、刻度与图例 8 pt，按插入宽度 1:1 生成，插入 LaTeX 时不再缩放。
- 尺寸：整栏图宽等于 `\textwidth`，半栏图宽 0.48 `\textwidth`；先在模板里用 `\the\textwidth` 实测后写入 style.py。
- 格式：矢量 PDF，字体嵌入（`pdf.fonttype = 42`）；视频幻灯片用同一脚本另存 300 dpi PNG。
- 图内不写标题，标题和结论写在 LaTeX 的 caption 中；去掉上边框和右边框，浅灰网格。
- 误差线一律为 1,000 次 bootstrap 的 95% 置信区间，图注写明。

**颜色编码原则**

1. 颜色只编码四类变量：方法、实体类型、数据集、错误类型。每个取值在全文只有一种颜色，图例顺序与下表一致。
2. 其他变量（训练数据量、示例数、扰动类型、输入表示、测试集）放在坐标轴、分面或线型上。例如输入表示对比图只有 BiLSTM-CRF 一个方法，所有柱子都用 BiLSTM-CRF 的颜色，表示类型放在横轴上。
3. 同一方法的变体用同色加纹理区分：无 CRF 版本、迁移版本、未见实体子集一律用斜线填充。
4. 折线图同时用不同的标记形状；堆叠柱加纹理并直接标注数值；LLM 提示与 LLM 标注蒸馏出现在同一张图时，在线条或柱子旁直接标注名称。
5. 热力图用顺序色图 cividis；表示增减的图用发散色图 PuOr，以 0 为中心。
